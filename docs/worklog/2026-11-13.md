## 사용자가 직접 할 폰 테스트 (미뤄 둠)

PWA 설정(manifest, 아이콘, 아이폰 meta)을 넣은 뒤 사용자에게 다시 안내한다. 지금은 홈 화면에 추가해도 주소창 없는 앱으로 열리지 않아 의미가 적다.

- [ ] 홈 화면에 추가 → 주소창 없이 열리는지 (아이폰, 안드로이드)
- [ ] 하단 탭 수업 → 공부 → MY 이동 후 뒤로 가기(안드로이드 뒤로 버튼)가 탭 사이를 오가지 않는지
- [ ] MY → 비밀번호 변경 → ← 로 MY에 돌아오는지
- [ ] 주소로 `/change-password`에 바로 들어가서 ← 를 누르면 MY 탭으로 가는지 (앱 밖으로 나가지 않음)
- [ ] 아이폰 아래쪽 홈 바에 하단 탭이 가리지 않는지, 위쪽 노치에 제목이 가리지 않는지
- [ ] 수업 탭 인사 "이름님, 문구"가 한 줄로 보이는지

PWA 작업 때 정할 것: 앱 아이콘(사용자 이미지 또는 에메랄드 배경 + 학사모/T), 홈 화면 앱 이름("Tutoring" 유지 여부). 사용자는 예약 작업을 먼저 하기로 했다.

### 결정한 것과 이유

- "이번만"은 1개 → 1개로 바꿀 때만 고를 수 있다. 여러 개를 한 번에 바꾸면 어느 수업을 어디로 옮길지 정할 수 없다. 더하기만·빼기만은 "이번만"이 예약·취소와 같아서 확인창에 안내만 보여 준다.
- "이번만"의 옮길 곳은 옛 수업과 시간이 가장 가까운 새 시간 수업 (같은 주 안의 것이 보통 골라진다, 시안 예: 11/19 목 → 11/18 수).
- 1시간 안에 시작하는 수업은 "앞으로 전부"에서도 그대로 둔다 (SCH-08). 확인창에 "1시간 안에 시작하는 수업은 그대로예요"를 보여 준다.
- 동시에 두 번 눌러도 한 번만 바뀌게 트랜잭션 처음에 내 학생 행을 잠근다 (updatedAt 갱신).
- 범위 계층은 where 안의 관계 조건에 범위를 붙이지 않아서, "이미 내 수업이 있는 슬롯" 판단은 내 수업을 따로 읽어서 한다.

### 결정한 것과 이유

- 선생님은 1시간 규칙 없이 수업 시작 전까지 바꿀 수 있다 (db-design에 적어 둔 대로). 이미 시작한 수업은 "지난 수업"과 같이 막는다.
- 선생님의 고정 일정 바꾸기는 "앞으로 전부"만 둔다. 한 번만 바꾸려면 앞으로의 수업에서 그 수업을 옮기면 되므로 같은 기능을 두 곳에 두지 않았다.
- 학생 로직을 복사하지 않고 같은 코드를 쓴 이유: 예약·되살리기·고정 수업 붙이기 규칙이 두 곳에서 어긋나지 않게. 학생 범위 계층을 그대로 써서 "그 학생 것만" 조건도 자동으로 붙는다.
- 이력은 수업 1회 변경도 같이 보여 준다 (요구사항 SCH-17은 고정 일정만 적혀 있었는데, db-design대로 한 테이블에 다 있고 선생님에게도 필요해서 넓혔다).
- DB 변경 없음 (schedule_change에 changed_by, reason이 이미 있었다).
