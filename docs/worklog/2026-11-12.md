## 선생님 범위 강제 계층 + 접근 차단 테스트

### 한 일

- `src/lib/db/scope.ts`: `teacherDb(teacherId)`, `studentDb(teacherId, studentId)`. Prisma 확장으로 모든 조회·수정에 범위와 `deleted_at IS NULL`을 붙인다. 자세한 규칙은 `docs/db-design.md` 2장 "범위 계층".
- ESLint: 기능 코드에서 `@/lib/db/client`를 import하면 오류.

- 테스트 시작 때 마이그레이션을 적용하고 테이블을 비운다 (`src/test/global-setup.ts`). 스키마 이름이 `_test`로 끝나지 않으면 바로 멈춘다.
- `src/lib/db/scope.test.ts` (47개):
  - 15개 테이블마다 선생님 A 범위에서 B 데이터를 조회·수정할 수 없음
  - 만들 때 teacher_id 자동, 다른 값 거부, 다른 선생님 학생·슬롯 연결 거부(복합 외래키)
  - include·_count에도 범위와 소프트 삭제 적용, delete·중첩 쓰기 차단
  - 학생 범위: 본인 것만, 수업 노트는 학생 노트만, 같은 슬롯 다른 학생 수업 안 보임, 선생님 본인 공부 기록 안 보임, 공개된 자료만, 다른 학생·선생님 글에 쓰기 불가
  - `RELATIONS` 목록이 스키마 관계와 같은지
- 일부러 범위 조건을 빼 보고 테스트가 실패하는지 확인했다 (teacher_id 조건 제거 시 30개, include 조건 제거 시 3개 실패).

### 결정한 것과 이유

- 테스트는 운영 DB(3306)가 아닌 test-mysql(3307)을 쓴다. 이 Mac mini의 3306이 곧 운영 DB라서, 테스트가 테이블을 비우다 사고가 나면 안 된다. 인투디헤븐 백엔드도 같은 컨테이너를 테스트에 쓴다.
- 범위 값과 다른 teacher_id가 들어오면 조용히 덮어쓰지 않고 오류를 낸다. 덮어쓰면 코드 실수가 숨는다.
- delete는 막았다. 소프트 삭제 정책이라 실수로 진짜 지우는 걸 원천 차단한다.
- 관계 필드 중첩 쓰기를 막았다. 중첩 create는 범위 확장이 안쪽 데이터까지 검사하지 못한다.
- 학생 범위도 이번에 같이 만들었다. 학생 화면 쿼리가 "본인 것만"을 매번 직접 쓰면 빠뜨리기 쉽다.

## 선생님 계정 생성 스크립트 + 관리자 계정

### 한 일

- `teacher.is_admin` 컬럼 추가 (마이그레이션 `teacher_is_admin`, 운영 DB 적용).
- `src/lib/auth/password.ts`: bcrypt(cost 12) 해시·확인, 비밀번호 규칙(8~72자).
- `src/lib/auth/accounts.ts`: `createTeacher`. 이메일은 소문자로 저장하고, 선생님·학생 테이블을 통틀어 중복이면 거부.
- `scripts/create-teacher.ts` (`npm run teacher:create -- --name 이름 --email 메일 [--admin] [--temp]`). 비밀번호는 실행 후 입력받아 명령 기록에 남지 않는다.
- 사용자 본인 계정을 관리자로 만들었다 (운영 DB 선생님 1명). 비밀번호 확인까지 했다.
- 테스트 6개 추가 (해시, 비밀번호 규칙, 이메일 중복·형식).

### 결정한 것과 이유

- 선생님 계정 생성은 어드민 기능으로 넣기로 했다 (사용자 요청). 로그인이 있어야 하므로 첫 관리자 계정만 스크립트로 만들고, 어드민 화면은 로그인 다음에 만든다.
- 누구나 선생님을 만들 수 있으면 안 되므로 `is_admin`으로 시스템 관리자만 허용한다.
- 로그인 화면이 선생님·학생 공용이라 이메일은 두 테이블을 합쳐 유일해야 한다.
- 본인 비밀번호는 직접 정한 것이라 강제 변경을 걸지 않았다. 어드민에서 만드는 선생님은 임시 비밀번호 → 첫 로그인 때 변경.
