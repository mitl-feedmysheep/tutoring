### 결정한 것과 이유

- 서버 액션 + `useActionState`로 폼 처리. API 라우트를 따로 두지 않아도 되고, 액션마다 `requireTeacher()`를 불러 세션 확인을 빠뜨리지 않게 했다.

- 링크 주소는 브라우저의 현재 주소(origin)로 만든다. 서버 환경변수로 도메인을 따로 관리하지 않아도 된다.
- 가입하면 바로 로그인시킨다 (AUTH-10). 개인정보 동의 문구는 7단계에서 넣는다.
- shadcn이 새로 넣은 `cn` 패키지 대신 기존 `@/lib/utils`의 `cn`을 쓰게 바꿨다.

- 어드민 메뉴를 인투디헤븐 어드민처럼 왼쪽 어두운 사이드바로. 메뉴는 "학생 관리" 하나, 안에 탭 "학생 목록"(`/admin/students`) / "초대 링크"(`/admin/students/invites`). 모바일은 햄버거 버튼으로 왼쪽 서랍(shadcn sheet).
- 어드민 화면은 라우트 그룹 `admin/(main)`에 넣어 로그인·비밀번호 변경 화면이 사이드바 레이아웃 밖에 있게 했다.
- 운영과 같은 조건(`DATABASE_URL=`)으로 빌드, 테스트 DB로 띄워 두 영역 흐름을 브라우저로 확인: 각 영역 미로그인 시 각 로그인 화면, 어드민에 학생 로그인 거부, 학생 초기화 → 웹앱 변경 화면, 임시 비밀번호 선생님 → 어드민 변경 화면, 어드민 로그아웃 → 어드민 로그인.

### 결정한 것과 이유

- 사용자 요청: 선생님도 학생과 같은 웹앱을 쓰고, 어드민은 주로 PC에서 따로 쓴다. 그래서 주소와 로그인 화면을 아예 나눴다.
- 로그인 상태도 분리했다 (사용자 요청: 서로 관련 없게). 쿠키를 `tutoring_session`(웹앱), `tutoring_admin_session`(어드민)으로 나누고, 토큰 audience에 영역을 넣어 한쪽 토큰을 다른 쪽 쿠키에 넣어도 통하지 않게 했다. 같은 브라우저에서 양쪽에 서로 다른 계정으로 로그인해도 되는 것까지 확인.
- 단, 비밀번호를 바꾸거나 초기화하면 session_version이 올라가서 양쪽 로그인이 모두 풀린다 (AUTH-10, 다른 기기 로그아웃과 같은 이유).
- 탭은 주소가 다른 링크로 만들었다. 새로고침·뒤로 가기에도 같은 탭이 열리고 각 탭이 서버에서 바로 데이터를 읽는다.
- 선생님 웹앱 화면 내용(오늘 수업, 본인 공부 기록 등)은 각 기능을 만들 때 채운다.

## 웹앱 화면을 인투디헤븐 웹앱에 맞춤

### 한 일

- 폰트를 Geist에서 Pretendard Variable(CDN dynamic subset, 인투디헤븐 웹앱과 같은 주소)로 바꿨다. Geist는 한글이 없어서 한글이 기기 기본 폰트(윈도우는 맑은 고딕)로 보였다. 어드민도 같이 바뀐다.
- 확대 막기(`maximum-scale=1, user-scalable=no`), 위아래 튕김·당겨서 새로고침 막기(`overscroll-behavior-y: none`), 라이트 모드 고정(`color-scheme: light`).
- 웹앱 폭을 인투디헤븐과 같은 `max-w-lg`(512px) 가운데 정렬로.
- 폰(390px)과 PC(1280px) 크기로 띄워 Pretendard 로딩, 폭, 가로 스크롤 없음 확인.

### 결정한 것과 이유

- 인투디헤븐 웹앱과 같은 사용감을 원해서 설정을 그대로 따랐다.
- 홈 화면 추가(PWA 매니페스트, 아이콘)와 하단 탭 메뉴는 5단계(PWA)와 기능을 만들 때 넣는다. 하단 탭을 넣을 때 아이폰 아래쪽 안전 영역(safe-area)도 같이 챙긴다.

## 어드민 태블릿 화면 정리

### 한 일

- 사용자가 태블릿에서 화면이 움직인다고 해서 아이패드 크기(768·820 세로, 1024·1180 가로)로 확인했다.
  - 세로: 왼쪽 메뉴가 폭 1/3을 차지해 달력 카드의 "명"이 줄바꿈되고, 학생 목록 표가 화면보다 넓어서 표만 좌우로 밀렸다.
  - 가로(1024): 오른쪽 패널까지 고정이라 달력 칸이 50px대로 좁아져 카드가 옆 칸으로 삐져나갔다.
- 왼쪽 메뉴 고정을 768px → 1024px 이상으로. 태블릿 세로는 ☰ 버튼 서랍.
- 달력 오른쪽 패널 고정을 1024px → 1280px 이상으로. 그보다 좁은 태블릿은 오른쪽에서 밀려 나오는 패널, 폰은 아래 패널.
- 달력 카드는 칸 폭을 넘지 않게 하고, 칸이 좁으면 "명"을 빼고 숫자만(컨테이너 쿼리).
- 학생 목록 표: 출생연도·성별은 1280px 이상, 가입일은 768px 이상에서만 보인다.
- 아이패드 4가지 크기 + PC 1440 + 폰 390에서 페이지·표 모두 가로로 밀리는 곳이 없는지 측정했다.
- 아이패드 크롬에서 달력을 스크롤하면 왼쪽 사이드바까지 올라가고 아래가 하얗게 비는 문제(사용자 제보): 사이드바를 sticky + `h-dvh`에서 fixed(화면 위아래에 붙임) + 본문 왼쪽 여백으로 바꿨다. 아이패드 크롬·사파리(WebKit)는 스크롤할 때 주소창이 줄며 화면 높이가 바뀌는데 sticky가 이때 풀렸다. 테스트 브라우저(크롬 계열)에서는 재현되지 않아서, 스크롤 끝에서 사이드바가 화면 위아래를 꽉 채우는지만 확인했다. 실제 아이패드 확인 필요.
