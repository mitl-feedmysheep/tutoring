### 결정한 것과 이유

- 테스트는 운영 DB(3306)가 아닌 test-mysql(3307)을 쓴다. 이 Mac mini의 3306이 곧 운영 DB라서, 테스트가 테이블을 비우다 사고가 나면 안 된다. 인투디헤븐 백엔드도 같은 컨테이너를 테스트에 쓴다.
- 범위 값과 다른 teacher_id가 들어오면 조용히 덮어쓰지 않고 오류를 낸다. 덮어쓰면 코드 실수가 숨는다.
- delete는 막았다. 소프트 삭제 정책이라 실수로 진짜 지우는 걸 원천 차단한다.
- 관계 필드 중첩 쓰기를 막았다. 중첩 create는 범위 확장이 안쪽 데이터까지 검사하지 못한다.
- 학생 범위도 이번에 같이 만들었다. 학생 화면 쿼리가 "본인 것만"을 매번 직접 쓰면 빠뜨리기 쉽다.

## 로그인, 초대 링크 가입, 비밀번호 초기화·강제 변경

### 한 일

- 세션: `src/lib/auth/token.ts`(jose HS256 서명), `session.ts`(쿠키 `tutoring_session`, HttpOnly, Domain 없음, 90일). `getAccount`가 서명 확인 뒤 DB에서 계정 상태(삭제·비활성·session_version)를 다시 확인한다.
- `requireTeacher()` / `requireStudent()`: 세션에서 teacherId(학생은 studentId까지)를 꺼내 `teacherDb`/`studentDb`를 돌려준다. 비밀번호 변경이 필요한 계정은 `/change-password`로 보낸다 (AUTH-08).
- 로그인(`login.ts`): 선생님·학생 공용, 이메일 대소문자 무시, 틀린 비밀번호와 없는 이메일은 같은 문구.
- 초대 링크(`auth/invite.ts`, `admin/invites.ts`): 32바이트 토큰, DB엔 SHA-256만. 발급·목록·취소는 teacherDb, 링크 확인과 가입은 원본 클라이언트. 가입은 `used_at` 조건부 UPDATE가 1행일 때만 학생 생성. 가입 입력은 zod로 검사.
- 비밀번호 초기화(`admin/students.ts`): `12341234`, `must_change_password`, session_version +1.
- 비밀번호 변경: 초기화된 계정은 현재 비밀번호 없이, 평소엔 현재 비밀번호 확인. 지금 비밀번호와 같으면 거부. 바꾸면 session_version +1 하고 쿠키 재발급.
- 화면: `/login`, `/invite/[token]`, `/change-password`, `/admin/students`(목록 + 초기화), `/admin/invites`(발급·목록·취소), `/`(학생 첫 화면 자리). shadcn button·input·label·card·badge·table·sonner 추가.
- 테스트 15개 추가 (총 69개). 선생님 간 격리: 다른 선생님의 초대 링크 목록·취소·발급, 학생 비밀번호 초기화가 막히는지, 토큰의 teacherId가 실제와 다르면 무효인지.
- 테스트 DB로 앱을 띄워 브라우저로 전체 흐름 확인: 로그인 → 링크 발급 → 가입 → 링크 재사용 차단 → 초기화 → 기존 로그인 끊김 → 임시 비밀번호 로그인 → 변경 전 다른 화면 차단 → 변경 → 링크 취소 → 학생의 /admin 접근 차단 → 로그아웃.

### 결정한 것과 이유

- 서버 액션 + `useActionState`로 폼 처리. API 라우트를 따로 두지 않아도 되고, 액션마다 `requireTeacher()`를 불러 세션 확인을 빠뜨리지 않게 했다.
- 미들웨어(proxy)는 두지 않았다. 레이아웃은 화면 이동 때 다시 그려지지 않으므로 페이지·액션마다 직접 확인하는 쪽이 확실하다 (Next.js 인증 가이드와 같은 방식).
- 토큰에 session_version을 넣고 매 요청 DB와 비교한다. 비밀번호 초기화·변경 때 다른 기기 로그인을 바로 끊을 수 있다.
- 로그인 실패 횟수 제한은 넣지 않았다 (사용자 결정). 메모리 방식은 재배포하면 풀리고, 소규모 과외 앱이라 관리할 정책을 늘릴 필요가 없다.
- 초대 링크 원본은 DB에 없어서 발급 직후 화면에서만 보여준다. 잃어버리면 새로 발급한다.
- 링크 주소는 브라우저의 현재 주소(origin)로 만든다. 서버 환경변수로 도메인을 따로 관리하지 않아도 된다.
- 가입하면 바로 로그인시킨다 (AUTH-10). 개인정보 동의 문구는 7단계에서 넣는다.
- shadcn이 새로 넣은 `cn` 패키지 대신 기존 `@/lib/utils`의 `cn`을 쓰게 바꿨다.
