# 요구사항 명세서

비대면 성인 영어 말하기 과외용 웹앱(PWA). 선생님 단위로 데이터가 완전히 분리되는 멀티테넌트 구조.

- 최초 작성: 2026-11-11
- 변경 이력은 맨 아래 "변경 이력"에 기록한다.
- 요구사항 ID(예: `SCH-03`)는 한 번 정하면 바꾸지 않는다. 삭제할 때는 취소선을 긋고 남겨둔다.

---

## 1. 사용자와 역할

| 역할 | 설명 |
|---|---|
| 시스템 관리자 | 관리자 표시(`is_admin`)가 있는 선생님. 어드민에서 다른 선생님 계정을 만든다. 첫 관리자 계정은 스크립트로 만든다 |
| 선생님 | 어드민 페이지 사용. 자기 학생 데이터만 볼 수 있음 |
| 학생 | 성인. 선생님이 발급한 초대 링크로 가입하고, 그 선생님에게만 소속 |

## 2. 기능 요구사항

### AUTH. 가입과 로그인

| ID | 내용 |
|---|---|
| AUTH-01 | 선생님이 학생마다 초대 링크를 발급한다. 1회용이고 발급 후 1시간이 지나면 만료된다. |
| AUTH-02 | 만료되거나 사용된 링크로 접속하면 안내 문구를 보여준다. 선생님은 어드민에서 링크를 다시 발급할 수 있다 |
| AUTH-03 | 가입 입력: 이름, 출생연도, 성별, 이메일, 비밀번호, 비밀번호 확인. 입력하면 바로 가입된다 (이메일 인증 없음) |
| AUTH-04 | 가입한 학생은 초대 링크를 발급한 선생님에게 자동으로 소속된다 |
| AUTH-05 | 직업 필드는 nullable이고 선생님이 어드민에서 입력한다 |
| AUTH-06 | 로그인은 이메일 + 비밀번호 |
| AUTH-07 | 선생님이 어드민에서 학생 비밀번호를 `12341234`로 초기화할 수 있다 |
| AUTH-09 | 선생님은 발급한 초대 링크 목록을 보고, 아직 쓰지 않은 링크를 만료 전에 취소할 수 있다 |
| AUTH-08 | 초기화된 계정은 다음 로그인 때 새 비밀번호 설정 화면으로 이동하고, 바꾸기 전까지 다른 화면을 쓸 수 없다 |

### SCH. 일정 관리

| ID | 내용 |
|---|---|
| SCH-01 | 선생님이 수업 슬롯(날짜, 시작·종료 시간)을 만들고 언제든 추가·삭제한다 |
| SCH-02 | 슬롯에는 정원 제한이 없다. 슬롯 카드에 참여 예정 학생 수를 표시한다 |
| SCH-03 | 학생은 아무 슬롯이나 예약할 수 있다 (1:1, 1:다 모두 가능) |
| SCH-04 | 학생은 선생님의 고정 수업 시간 중에서 고정 일정(예: 매주 화·목 19시)을 고를 수 있고, 그 시간의 슬롯이 만들어지면 자동으로 예약된다 |
| SCH-05 | 학생은 특정 회차만 취소하거나 다른 슬롯으로 옮길 수 있다 |
| ~~SCH-06~~ | ~~예약 가능 기간은 1~2주 앞까지다~~ → SCH-13 |
| SCH-07 | 주당 수업 횟수 제한은 없다 (기본 2회) |
| SCH-08 | 취소·변경은 수업 시작 30분 전까지 가능하다. 예약 페이지에 이 규칙을 표시한다 |
| SCH-09 | 취소·변경은 선생님 승인 없이 바로 반영되고 선생님에게 알림이 간다 |
| SCH-10 | 선생님이 예약된 학생이 있는 슬롯을 삭제하면 해당 학생들에게 알림이 간다 |
| SCH-11 | 선생님은 매주 반복되는 고정 수업 시간(요일, 시작·종료 시간)을 등록한다. 매달 마지막 날 다음 달 전체 슬롯이 고정 시간에 맞춰 만들어지고, 학생 고정 일정에 맞춰 수업도 일괄로 만들어진다. 월 중간에 등록하면 남은 날짜만큼 바로 만든다. 특정 날만 쉬려면 그 날 슬롯을 삭제한다 |
| SCH-12 | 고정 수업 시간과 별도로 1회성 슬롯도 열 수 있다 |
| SCH-13 | 학생은 만들어져 있는 앞으로의 슬롯(이번 달, 생성됐으면 다음 달까지)을 언제든 예약·취소·변경할 수 있다. 지난 수업은 바꿀 수 없고, 30분 전 규칙(SCH-08)은 그대로 적용한다 |
| SCH-14 | 학생이 고정 일정을 바꾸면 "이번만 / 앞으로 전부"를 고른다. 앞으로 전부를 고르면 이미 만들어진 앞으로의 수업도 일괄로 바뀌고, 다음 달부터도 새 일정으로 만들어진다 |
| SCH-15 | 선생님이 고정 시간을 바꾸거나 지울 때, 그 시간에 고정 일정을 둔 학생이 없으면 바로 반영한다. 있으면 이번 달은 그대로 두고 다음 달부터 반영한다. 시간을 바꾼 경우 학생 고정 일정은 새 시간으로 따라가고, 지운 경우 학생 고정 일정은 이번 달 말에 끝난다. 학생 일정 화면에 바뀌는 내용을 안내한다 (푸시 알림 없음) |
| SCH-16 | 선생님은 학생의 수업과 고정 일정을 직접 바꿀 수 있다. 지난 수업은 바꿀 수 없다. 바꿀 때 사유를 반드시 적고, 학생 알림에 사유가 함께 간다 |
| SCH-17 | 고정 일정 변경 이력(언제, 누가, 무엇에서 무엇으로, 사유)을 남기고 선생님이 학생 카드에서 볼 수 있다 |

### MEET. 화상 수업 (Google Meet)

| ID | 내용 |
|---|---|
| MEET-01 | 선생님이 자기 구글 계정을 앱에 한 번 연결한다 |
| MEET-02 | 슬롯마다 Google Calendar API로 Meet 링크를 자동 생성한다. 같은 슬롯의 학생들은 같은 링크로 들어온다 |
| MEET-03 | 예약한 학생을 캘린더 참석자로 추가해서 입장 승인 없이 들어올 수 있게 한다 |
| MEET-04 | 선생님과 학생 모두 앱의 수업 카드에서 바로 입장한다 |

참고: 개인 Gmail 계정은 3명 이상 회의가 60분으로 제한된다.

### ADMIN. 선생님 어드민

| ID | 내용 |
|---|---|
| ADMIN-01 | 학생 목록과 학생 카드 (프로필, 직업 수정, 수업 이력, 노트, 공부 기록, 납부 내역) |
| ADMIN-02 | 초대 링크 발급, 비밀번호 초기화 |
| ADMIN-03 | 대시보드 구성은 추후 결정 |
| ADMIN-04 | 선생님이 학생을 비활성화할 수 있다. 비활성 학생은 로그인과 예약이 막히고 목록에서 숨겨진다. 기록은 남고 다시 활성화할 수 있다. 비활성화하면 같은 이메일로 새 계정을 만들 수 있다. 그 이메일로 새 계정이 이미 있으면 예전 계정은 다시 활성화할 수 없다 |

## 3. 비기능 요구사항

| ID | 내용 |
|---|---|
| NFR-01 | **데이터 격리**: 선생님 간 학생 데이터는 완전히 분리된다. 선생님 소유 데이터는 모두 `teacher_id`를 가지며, 앱의 모든 조회·수정은 로그인한 선생님 기준으로 범위가 제한된다 |
| NFR-02 | 격리는 여러 겹으로 보장한다: DB 접근 공통 계층에서 `teacher_id` 강제, 서로 다른 선생님 데이터끼리 연결되지 않도록 복합 외래키, 선생님 간 접근 차단 테스트 |
| NFR-03 | `teacher_id`는 항상 서버 세션에서 가져온다. 클라이언트가 보낸 값은 쓰지 않는다 |
| NFR-04 | 파일은 비공개로 저장하고, 권한 확인 후 짧게 유효한 서명 URL로만 내려준다 |
| NFR-05 | PWA로 홈 화면에 추가할 수 있다. 웹 푸시는 iOS 16.4 이상에서 홈 화면 추가 후 동작한다 |
| NFR-06 | 모든 시간은 UTC로 저장하고 KST로 표시한다 |
| NFR-07 | 학생 화면은 모바일 우선, 어드민은 데스크톱·태블릿 우선 |
| NFR-08 | 모든 데이터는 소프트 삭제한다. 삭제하면 `deleted_at`만 기록하고, 삭제된 데이터는 앱 어디서도 읽지 않는다 |

## 4. 범위 밖

성적 기록, 학습 목표, 학부모 계정, 월간 리포트, 숙제 제출, 과외비 금액 설정, 회차 관리, 납부 안내 알림, 선생님 셀프 가입, 결제.

## 5. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js (App Router), React, TypeScript | 프론트·백엔드 통합 |
| DB | MySQL | 기존 서버에 별도 스키마 생성 |
| ORM | Prisma | mitl admin과 동일 |
| 파일 저장 | Cloudflare R2 (S3 호환) | 과외 앱 전용 비공개 버킷. 서명 URL로만 접근 |
| 웹 푸시 | web-push (VAPID) | mitl admin과 동일 |
| 화상 수업 | Google Calendar API (googleapis) | Meet 링크 생성 |
| 알림 스케줄러 | Next.js 프로세스 안에서 1분마다 실행 | 발송 기록을 남겨서 중복 발송 방지 |
| UI | shadcn/ui, Radix UI, Tailwind CSS, lucide-react, sonner | mitl admin과 동일 |
| 폼 | react-hook-form + zod | mitl admin과 동일 |
| 인증 | jose (JWT, HttpOnly 쿠키) + bcryptjs | mitl admin과 동일 |
| 테스트 | vitest | mitl admin과 동일 |
| 배포 | Mac mini 셀프 호스팅 + Docker | mitl admin과 같은 방식 (아래 참고) |
| 도메인 | `tutoring.intotheheaven.app` | |

### 배포 (mitl admin 방식 재사용)

```
main 브랜치 push
  → GitHub Actions (Mac mini의 self-hosted runner)
  → npm ci, 테스트
  → docker buildx로 이미지 빌드 (Next.js standalone)
  → Doppler에서 환경변수를 받아 docker run (--restart unless-stopped)
  → curl 헬스체크
  → Cloudflare Tunnel이 도메인을 Mac mini 컨테이너 포트로 연결
```

과외 앱에 맞게 달라지는 점:
- 포트: 3010
- 도메인: Cloudflare Tunnel에 `tutoring.intotheheaven.app` 추가
- Doppler: 과외 앱 전용 프로젝트 `tutoring`. 운영(prd) 환경 하나만 쓴다 (별도 개발 환경 없음, 테스트도 운영에서)
- R2: 버킷 `tutoring-prod` 하나. 이 버킷에만 권한이 있는 토큰 사용
